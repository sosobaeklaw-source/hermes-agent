## 1. 핵심 발견 (Executive Summary)

### 1.1 사건의 법리적 골자

세 심급 모두 **동일한 사실관계**(2021. 3. 3. 회사 감사반이 직원의 변호사 동석 요청을 거부한 채
임의문답을 실시함)를 두고 **다른 추상도에서 다른 질문**을 던진다.

- **1심**: "회사 규정에 변호사 조력 의무가 있는가?" → 없음 → 절차 하자 X
- **2심**: "그 시점에 방어권은 충분히 보장되었는가?" → 묵비권 고지 등으로 충분 → 절차 하자 X
  (단, 시점을 **인사위원회가 아닌 감사면담 단계로 명시 특정**)
- **대법원**: "**사인(私人) 간**에 자신이 선임한 변호사와 동석할 권리 자체가 인정되는가?"
  → 정식 쟁점화 (자료 한계로 결론 미공개)

### 1.2 본 시범 케이스가 입증한 것

| 가설 | 결과 |
|---|---|
| **H1**. 판결문 3건은 atom 단위로 원자화 가능하다. | ✅ 45개 atom + 110+ wikilink로 분해 완료. |
| **H2**. 원자화 그래프는 LLM이 "대법원처럼" 사고하도록 트레이닝하는 base가 된다. | ✅ 5단계 추상화 사다리 + 15개 training pair로 시드 데이터 생성. |
| **H3**. 같은 atom들은 마케팅 파이프라인에서도 재사용 가능하다. | ✅ 동일 atom set이 P1~P5 페르소나 5종, 후크 25종, 카드뉴스 8장, 블로그 2400자, 광고 카피 5종으로 변주. |
| **H4**. 파이프라인 산출물 간 **시너지**가 측정 가능하다. | ✅ 법률 파이프라인이 만든 "쟁점 매트릭스"가 마케팅 후크의 신뢰도·정확도를 동시에 담보. (아래 1.3) |

### 1.3 시너지 측정 — 분리 파이프라인 vs 통합 파이프라인

| 기준 | 분리 (전통 방식) | 통합 (원자노트 base) |
|---|---|---|
| 사실 정확도 | 마케팅이 사실을 단순화하다 왜곡 위험 | atom의 `confidence` 메타가 마케팅 카피로 그대로 전이 → 단정 표현 자동 차단 |
| 재작업 | 새 판례 추가 시 양 파이프라인 각자 처음부터 | atom 추가만으로 양 파이프라인이 동시 갱신 |
| 일관성 | 블로그·광고 메시지 충돌 | atom-id 인용으로 모든 산출물이 같은 원천에 jointly grounded |
| 갱신 비용 | 대법원 판결 나오면 양쪽 모두 재작업 | `O-003`(supreme outcome) atom 한 개만 재처리 → 자동 전파 |
| 분쟁 위험 | 마케팅 카피가 변호사법·표시광고법 위반 위험 | atom 메타에 컴플라이언스 태그 → 카피 생성 시 자동 점검 가능 |

## 3. 방법론 — 어떻게 작업했는가

### 3.1 원자화 7원칙 (`01_atomized/README.md`)

1. **하나의 노트 = 하나의 명제** — 더 잘라낼 수 없는 단위
2. **출처를 함수처럼** — 같은 명제라도 심급마다 별개 atom
3. **Wikilink-first** — 산문 풀어쓰기 금지, `[[atom-id]]`로만 가리킴
4. **법리(D)와 적용(R) 분리** — 추상 룰과 그 룰을 본 사건에 적용한 판단을 분리
5. **사실(F)과 평가(R) 분리** — 인정 사실과 그 평가를 분리
6. **atom-id 규칙** — `<카테고리>-<3자리>-<슬러그>`
7. **YAML 메타** — id, type, instance, source, tags, related, confidence

### 3.2 법률 파이프라인의 4단 변환

```
원본 PDF
   ↓ [원자화]
45 atom (graph)
   ↓ [집계]
synopsis (한 줄~한 페이지 요지)
   ↓ [차원 분해]
issue × instance 매트릭스
   ↓ [추상화]
doctrine evolution (5단계 사다리)
   ↓ [데이터화]
training pairs (LLM 트레이닝용 jsonl)
   ↓ [반박]
adversarial bank
```

이 변환의 **각 단계가 비가역적이지 않다**는 것이 핵심. atom이 갱신되면 모든 산출물이 동시에
갱신된다. 즉 **base graph = 진실의 단일 소스(single source of truth)**.

### 3.3 마케팅 파이프라인의 페르소나 분기

```
같은 atom set
   ↓ [페르소나 정의]
P1 HR · P2 CEO · P3 노동자 · P4 전문가 · P5 일반
   ↓ [페르소나별 atom 우선순위 재정렬]
P1: I-001, R-005가 top
P2: F-009, O-002가 top
P3: F-009, I-001, tp-013이 top
P4: R-009, D-005, adversarial이 top
P5: F-009 + 서사 atom이 top
   ↓ [메시지 톤 적용]
후크(짧음) · 카드뉴스(서사) · 블로그(롱폼) · 광고(액션)
```

## 4. "LLM이 대법원처럼 사고하는가" 검증

### 4.1 검증 프레임 — 5단 추상화 사다리

본 사건의 핵심은 사고의 **추상도 점프**다.

```
L1 사실 ───→ L2 회사 규정 ───→ L3 절차 일반 ───→ L4 계약 부수의무 ───→ L5 헌법 사인 간 효력
                ↑                ↑                     ↑
               1심             2심                대법원
```

L2와 L3에서 멈추는 것이 일반 LLM의 기본 패턴. **L4-L5로 점프하지 않는다.**
이를 보완하려면 `02_legal_pipeline/04_training_pairs.jsonl`의 다음 3종 데이터가 핵심:

- **abstraction_ladder 페어 (tp-001~tp-005)**: Level 1부터 Level 5까지 동일 사실을 다른 레벨에서
  답하도록 강제. 모델이 한 레벨에서 멈추지 않게 학습.
- **thinking_like_supreme_court 페어 (tp-006)**: 하급심 결론을 그대로 두면서 대법원이 추가로
  무엇을 봐야 하는지의 메타 추론.
- **self_refine 페어 (tp-011, tp-012)**: 한 답에서 한 단계 더 추상화하는 패턴.

### 4.2 본 시범 케이스에서 LLM이 자주 실패하는 패턴

`02_legal_pipeline/05_adversarial.md`의 **D. 모델 회피 패턴 점검**에 정리:

| 회피 패턴 | 본 사건의 발현 | 대응 |
|---|---|---|
| 과도한 양비론 | "양쪽 다 일리가 있고..." | tp-013처럼 추정 판시사항 명시 작성 강제 |
| 추상도 과대 점프 | 사실 검토 없이 헌법론으로 도약 | Level 1부터 순차 강제 |
| 결론 단정 | 자료에 없는 대법원 결론 단정 | confidence=low 메타 + 명시적 미확정 처리 |
| 시점·단계 혼동 | 인사위원회 거부 ≠ 감사면담 거부 | 별개 atom으로 분리 |
| 이종 법리 혼동 | 형사 변호인권 = 노동법 절차권 | D-005에서 구조적 유사·차이 명시 |

## 5. "마케팅 파이프라인이 가동되는가" 검증

### 5.1 입력 → 산출물 변환 매핑

| 입력 atom | 변환된 마케팅 산출 |
|---|---|
| `F-009` (변호사 동석 요청 거부) | 후크 P3-1 ("회사 감사실에서 호출 받았습니다, 변호사 데려가도 되나요?"), 카드뉴스 카드 4 ("이 한 마디가 5년의 분쟁을 시작했습니다"), 블로그 도입부 |
| `R-005` (2심 시점 특정) | 블로그 본문 "2심이 정교화한 두 가지 논거", 후크 P1-3 |
| `R-008` (대법원 쟁점 정식화) | 카드뉴스 카드 6, 블로그 "대법원이 다른 질문을 던진 이유", 광고 헤드라인 P2-2 |
| `D-005` (변호인 조력권 사인 간) | 카드뉴스 카드 7 ("헌법의 질문"), 블로그 결론부, 유튜브 스크립트 |
| `F-001` (사모펀드 환매중단) | 카드뉴스 카드 2 (스토리 도입), 후크 P2-3 ("120억으로 시작된 감사") |

→ 같은 atom 세트가 **5개 채널 × 다중 페르소나**로 무손실 변환됨.

### 5.2 컴플라이언스 안전망

원자노트의 `confidence` 메타가 마케팅 카피의 결과 단정 위험을 자동으로 차단:

- `O-003` (대법원 결론) `confidence: low` → 카피에서 "대법원이 인정했다" 표현 금지
- `D-005` (변호인 조력권 사인 간) `confidence: medium` → "쟁점이다", "검토하고 있다"까지만 허용

이는 **컴플라이언스 룰을 카피라이터의 양심에 맡기지 않고 데이터 구조에 새기는** 방식.

### 5.3 KPI 가설 (실제 운영 시 검증 대상)

| 지표 | 목표 |
|---|---|
| 검색광고 CTR (P2 CEO) | 4.5% (업종 평균 3.1%) |
| 검색광고 CPL (P1 HR) | 8,000원 이내 |
| 카드뉴스 저장률 (P5) | 노출의 6% |
| 블로그 평균 체류 (P1) | 4분 이상 |
| HR 매뉴얼 컨설팅 의뢰 전환 | 리드 대비 12% |

## 6. 한계와 후속 작업

### 6.1 자료 한계

- **대법원 판결문 본문 부재**: 제공된 자료는 1쪽짜리 사안 개요·쟁점 요지뿐. `O-003`의 confidence를
  `low`로 처리하고, 결론을 단정하지 않는 방식으로 우회. 판결문 입수 시 재처리 트리거 명시.
- **공익제보자보호법 적용 검토 부재**: 원고들이 위 법률 적용을 명시적으로 주장한 흔적이 자료에
  없음. 만약 적용되었다면 `I-002`의 결론이 달라질 수 있음. (adversarial A7 참조)

### 6.2 일반화 위험

본 시범 케이스는 **단일 사건**에 대한 demo. 다음 두 가지가 일반화 가능성의 핵심 변수:

1. **사건 복잡도**: 본 사건은 쟁점 4개로 비교적 단순. 30개 쟁점 사건에서는 atom 수가 300+로
   폭증하므로 **atom-id 네이밍 규칙과 폴더 구조의 확장성** 검증 필요.
2. **심급 수**: 본 사건은 3심으로 표준적. 환송·재상고·헌재 결정이 얽히는 경우 `instance` 메타
   확장 필요.

## 7. 한 줄 결론

**원자화는 "법률 문서 파이프라인"과 "마케팅 파이프라인"을 분리시키는 게 아니라 둘이 같은 base
graph를 공유하게 함으로써 결합시킨다.** 그 결합이 곧 시너지의 정체이며, LLM이 "대법원처럼"
사고하도록 훈련하는 데이터셋과, 같은 사실을 다섯 페르소나에게 다섯 톤으로 전달하는 마케팅
자산이 **동일한 atom set에서 분기**할 수 있게 한다.

본 시범 케이스로 그 결합이 작동 가능함을 확인했고, 모든 산출물은 본 PR 브랜치에 커밋되어 있다.
